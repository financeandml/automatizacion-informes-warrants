# stock-screener

- **Repo / alcance / licencia**: `github.com/RyanJHamby/stock-screener` (copia local `scratchpad/repos/stock-screener-main`). Alcance: todo el repo. Licencia **MIT** (`LICENSE`, © 2024 Ryan Hamby). Paquete `src` v0.1.0. Es un *screener* técnico de swing trading (Minervini/Weinstein, fases 1-4) sobre unas 3.800 acciones de EEUU con yfinance, no un generador de informes de análisis.
- **Cobertura**: **2.700 archivos** = 86 fuera de `data/` + 2.614 en `data/`.
  - **Leídos completos (22)**: `requirements.txt`, `config.yaml`, `.env.example`, `.gitignore`, `LICENSE`, `.github/workflows/tests.yml`, `.github/workflows/daily_screening_git_storage.yml`, `.github/dependabot.yml`, `CONTRIBUTING.md`, `docs/README.md`, `run_screen.sh`, `run_test.sh`, `scripts/daily_scanner.sh`, `examples/example_entry_dates.json`, los 6 `__init__.py` (`src/`, `src/data/`, `src/analysis/` (vacío), `src/notifications/`, `src/screening/`, `tests/`), `src/data/fetcher.py` y `src/data/fundamentals_fetcher.py`.
  - **Solo firmas + cabecera + partes relevantes (63)**: los 31 `.py` restantes. De `storage.py`, `quality.py`, `git_storage_fetcher.py`, `universe_fetcher.py`, `benchmark.py`, `phase_indicators.py`, `email_notifier.py` y `dashboard.py` se leyeron además los modelos, las constantes y los fragmentos clave. Se suman los 24 `.md` (índice de encabezados, más el README parcial y el arranque del CHANGELOG) y `scripts/check_throttling.sh`.
  - **Por muestreo (2.615)**: `assets/example-output.png` (visto) y los 2.614 archivos de `data/`. Se muestrearon `AAPL_fundamentals.json` (completo), el JSON más pequeño (`EIC`), `metadata.json` (cabecera y recuento) y `latest_optimized_scan.txt` (80 líneas más el recuento de secciones). Con `grep` se contaron las claves y los `NaN` de los 2.574 JSON y la distribución de `fetched_at`. Los `.pkl` solo se enumeraron (no se deserializan porque `pickle` no es de confianza).

## Riesgos

| Riesgo | Detalle |
|---|---|
| Licencia | MIT: se puede copiar conservando el aviso de copyright. Sin riesgo |
| Fuente de datos frágil | yfinance (scraping no oficial de Yahoo; *rate limits* documentados en 3 docs). FMP `/api/v3` son endpoints antiguos. Universo vía `ftp://ftp.nasdaqtrader.com` (FTP, que puede fallar con `pd.read_csv`) |
| Bug en el universo | `_filter_stocks` descarta cualquier ticker que **termine** en W/R/U (p. ej. `NOW`, `SNOW`, `AMZN` no, pero sí `TSLR`…): pierde empresas válidas |
| Seguridad | `pickle.load` en caché y progreso (ejecución de código si la caché se manipula). `dashboard.py` `/api/scan?path=` lee **cualquier archivo** (path traversal) y escucha en `0.0.0.0`. El workflow tiene `contents: write` y hace commit automático de datos |
| Calidad de datos | 2.255 de 2.574 JSON con `NaN` (no es JSON válido para parsers estrictos). Cobertura de márgenes e inventario incompleta. Datos de una sola fuente sin conciliar |
| Windows | Scripts bash con `source venv/bin/activate`; `dashboard.py` usa `venv/bin/python` (con *fallback* a `sys.executable`). `open(..., 'w')` sin `encoding` y `Path.read_text()` sin `encoding` con emojis en los informes: `UnicodeEncodeError` probable con cp1252 en Windows. `run_screen.sh` y `run_test.sh` tienen rutas rotas |
| Python 3.13 | README y CONTRIBUTING piden 3.13+, pero el CI prueba con 3.12. `datetime.utcnow` (5 usos) está obsoleto desde 3.12. `declarative_base` de `sqlalchemy.orm` funciona en 2.x, pero es estilo antiguo. Dependencias muy fijadas (`pandas==3.0.5`, `numpy==2.5.2`) que pueden chocar con edgartools |
| Calidad general | Repetición (`import math` dentro de cada `if`, tres fetchers solapados: `fetcher`/`smart_fetcher`/`git_storage_fetcher`, dos *batch processors*). `logging.basicConfig` en cada módulo. Docs desactualizadas respecto al código. Tests reales solo para `fetcher`, `quality` y `screener` |
| Peso del repo | `data/` versionado (unos 15 MB y 2.614 archivos) por los commits diarios del bot: no copiar esa práctica |
